# Release plan

Each release is a vertical, testable dependency for the next. Feature states live in `FEATURE_REGISTRY.yaml`; this plan is not evidence of implementation.

## R0 - Foundation heartbeat

Prove one real Flutter/generated-client/FastAPI/PostgreSQL path, repository controls, minimal local runtime, resource guard, structured errors/logs, initial visual system, CI, and automatic evidence. Active brief: `docs/program/releases/R0_FOUNDATION_HEARTBEAT.md`.

Exit: clean bootstrap instructions; real readiness visible through the same-origin Flutter web build in an automatically verified Chrome phone viewport and through the Android debug application on an emulator/capable runner or attached device; all mandatory R0 Tier 1/2 tests pass; no critical repository or supply-chain finding; independent quality, security, UX, and integration review. Missing tooling or Android runtime evidence blocks this exit rather than waiving it. The broader physical-device matrix, iOS, signing, and brand approval remain separate pending evidence.

## R1 - Adult manual wellness core

Add provider-neutral identity, adult onboarding/consent, profile/preferences, ownership and roles, approved/synthetic evidence review, lexical grounded answers with abstention, manual meals and deterministic sourced nutrition, safe deterministic plans, progress, minimal operational admin workflow, export, and selected-record deletion.

Dependency: verified R0 contracts and runtime. Exit: all named adult demo journeys use real backend persistence without vision.

## R2 - Meal candidate assistance

Add privacy-aware uploads, file/metadata validation, quality feedback, region and top-k candidates, unknown/abstention, mandatory confirmation/correction, ranges, fixture provider, evaluation harness, and truthfully recorded real-adapter status. Manual R1 completion remains permanent.

Dependency: integrated R1 manual meal flow and approved image data/retention contract.

## R3 - Movement, routes, nearby places, optional pose

Add reviewed workouts, offline-resilient route recording/sync, endpoint privacy transforms, maps/nearby provider interfaces and demo path, external navigation, plus exactly two human-selected experimental on-device pose flows. Raw pose frames stay on-device by default.

Dependency: frozen permission, privacy, offline, deletion, and exercise contracts. Physical-device results remain pending until performed.

## R4 - Measured advanced intelligence

Consider hybrid retrieval/reranking, claim verification, multimodal input, portion experiments, wearables, low-risk personalization, Sesotho resources/benchmark, contextual presentation/reminder experiments, regional food evaluation, and model/dataset promotion metadata. Every capability is optional, independently benchmarked, reversible, and feature-flagged.

Dependency: stable core workflow and named dataset, licence, language, privacy, security, and domain gates.

## R5 - Operational hardening

Complete implementation security reviews, scans/SBOM, privacy-safe logs/metrics/traces/alerts, performance, retention jobs, backup/restore, migration/rollback, outage resilience, reference deployment, Android release build, operating runbooks, and release-readiness evidence.

Dependency: R0-R4 code-complete scope. No automatic deployment or production approval.

## R6 - Controlled-pilot package

Prepare physical-device, domain, language, privacy/legal, security, dataset, user-acceptance, app-store, support, incident, and pilot-monitoring packs. Humans execute and approve gates requiring people, judgement, credentials, stores, real datasets, or devices.
